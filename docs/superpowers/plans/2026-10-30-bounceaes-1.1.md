# BounceAES Master 1.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Dante-style routing, PTP master election and Windows audio (app/device capture, device playback incl. VB-CABLE) to BounceAES Master without a kernel driver.

**Architecture:** Every source writes stereo pairs onto the shared PTP timeline and declares a readiness delay `D_src`; every destination reads its routed source at `now − D_src`. The PTP slave becomes a port that can also act as master (BMCA). A new user-session process (Audio Bridge) moves audio between WASAPI endpoints and the timeline with PI-controlled variable-rate resampling.

**Tech Stack:** C++20, CMake, existing core/platform/engine libraries; libsamplerate 0.2.2 (BSD-2, vendored); WASAPI/MMDevice/ActivateAudioInterfaceAsync (Windows 11).

**Spec:** `docs/superpowers/specs/2026-10-30-bounceaes-routing-ptp-windows-design.md`

## Global Constraints

- Version 1.1.0; config `"version": 2`; shared memory `BounceAESMaster.v2`, layout version 2.
- Stereo pairs only; one source per destination; no summing; silence for missing sources.
- Limits: 32 subscriptions, 32 AoIP outputs, 32 ASIO pairs each way, 16 Windows sources, 16 Windows destinations.
- Route ids: `net-in:N`, `net-out:N`, `asio-out:N`, `asio-in:N` (N = 1..32), `win-app:<exe>`, `win-loop:<endpoint id>`, `win-in:<endpoint id>`, `win-out:<endpoint id>`.
- `D_src`: net-in = subscription latency; asio-out = 0; win-* = 20 ms (960 frames).
- PTP roles `auto` (priority1 250), `preferred` (100), `slave`; priority2 128; clockClass 248, accuracy 0xFE, variance 0xFFFF, timeSource 0xA0; Announce 1/s (log 0), Sync two-step 8/s (log −3); master after 3 s of being best; foreign master timeout max(3 intervals, 6 s).
- SDP session name `"<station_name> / <output name>"`; station_name defaults to the computer name.
- Tests never send multicast outside 127.0.0.1. UI text Polish; panel stays in the dark minimalist style.
- Every source file starts with `// SPDX-License-Identifier: GPL-3.0-or-later` (vendored code keeps its own header).

Rules: role Slave never masters; own dataset competes in BMCA; become Master after own dataset was best for 3 s (Listening→Master, or Locked/Holdover→Master on master loss); a better foreign Announce switches Master→Listening immediately; Follow_Up precise origin = `clock.to_ptp(tx_local)`; Delay_Resp receive timestamp = `clock.to_ptp(rx_local)`; own Announce/Sync ignored on receive (source == self).

### Task 7: Windows Audio Bridge, engine integration, tray supervision

**Files:** Create `bridge/bridge_main.cpp`, `bridge/wasapi_stream.hpp`, `bridge/wasapi_stream.cpp`, `bridge/endpoints.hpp`, `bridge/endpoints.cpp`, `bridge/bridge.rc`; modify `CMakeLists.txt`, `engine/src/engine.cpp` (request JSON from routes, read report into RoutingView), `tray/tray_main.cpp`, `installer/nsis/BounceAES-setup.nsi`, `installer/install.ps1`, `installer/uninstall.ps1`.

Behaviour:
- Bridge: single instance (claims `bridge_pid`), heartbeat every 100 ms; every 500 ms reads request, reconciles streams; every 1 s writes report (endpoints via IMMDeviceEnumerator, apps via IAudioSessionManager2 on render endpoints, slot states, peaks); `win_src_delay_frames = 960`.
- Capture stream (win-app via ActivateAudioInterfaceAsync process loopback incl. tree / win-loop via AUDCLNT_STREAMFLAGS_LOOPBACK / win-in): event-driven shared mode 10 ms, convert to float stereo, DriftResampler with base ratio 48000/device_rate and RateController keeping FIFO at 480 frames; writer thread writes FIFO into `win_src(slot)` at contiguous positions starting at `now_sample` (re-anchored if |position − now| > 4800).
- Render stream (win-out): reads routed source ring at `now − delay − 480`, resamples to device rate with RateController on the device buffer padding (target 480 frames), writes to IAudioRenderClient.
- Errors: device invalidated / process gone → slot `ok=false` with reason, retry every 2 s.
- Engine: builds BridgeRequest from routes (win sources get slots 1..16 by first appearance), win-src rings as sources with D_src = `win_src_delay_frames`; RoutingView adds Windows endpoints/apps from the latest report (sources: apps `win-app`, render endpoints `win-loop`, capture endpoints `win-in`; destinations: render endpoints `win-out`); bridge absent (heartbeat stale > 2 s) → Windows nodes unavailable "brak sesji użytkownika".
- Tray: starts `BounceAESAudioBridge.exe` (same directory) at launch, restarts after 2 s if it exits, back-off 30 s after 3 failures within 1 min, terminates it on "Zakończ".
- Installer: install/remove `BounceAESAudioBridge.exe`.
