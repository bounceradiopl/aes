# BounceAES Master 1.2.2 — panel hardening (port of the Bounce Encoder 1.0 HTTP fixes)

Goal: close the BounceAES Master panel weaknesses found while building Bounce Encoder, reusing the encoder's tested solutions (encoder/src/http_server.cpp, encoder/src/login_throttle.cpp, tests/test_encoder_http.cpp). No audio/ASIO/bridge behaviour change.

## Changes (engine/src/http_server.cpp unless noted)
1. One request per connection: `set_keep_alive_max_count(1)` (universal anti-smuggling guarantee; the pre-routing 401 and any httplib early refusal can no longer leave a body to be parsed as further requests).
2. Pre-routing allowlist before any body is read: methods GET/POST/PUT/DELETE only (405); any Content-Encoding → 415; Range on /api → 416; Transfer-Encoding, POST/PUT without Content-Length, malformed/duplicate Content-Length, Content-Length > 1 MB → 411/400/413; multipart → 415.
3. After the body is read (single guard wrapper for every route, like the encoder): POST/PUT with a body must be exactly application/json (charset allowed) → 415; then the session check (401) for protected routes. Make sure every protected route goes through the one wrapper.
4. /api/setup: local only AND Host header a loopback literal (127.0.0.1, localhost, [::1], optional port) → else 403 (DNS rebinding); the "no password yet" check repeated under the change mutex (setup race → 409).
5. Login throttling without sleeping a pool thread (port LoginThrottle: 5 failures/60 s per address → 30 s block, 429, global ceiling for remote addresses, loopback exempt from the ceiling only); remove the 500 ms sleep.
6. /api/live (SSE): non-sliding session check on every event (SessionStore::alive exists in core), closes after logout/expiry; a password change revokes all other sessions; a login that verified the old hash during a password change gets no session (generation check).
7. httplib lost-stop race: start()/stop() wait until the server is listening or its thread has ended (port the encoder's fix), so stop() right after start() never hangs.
8. Version 1.2.2 in every version file (CMakeLists.txt, core/include/bam/constants.hpp, bridge/bridge.rc, tray/tray.rc, service/service.rc, installer/nsis/BounceAES-setup.nsi); docs/INSTALL.md + README "Co nowego w 1.2.2" (Polish, short): panel safety changes, and that the panel now needs JSON clients (the bundled panel and tray already comply).
9. Not changed (document as known limitations in INSTALL.md, same wording as the encoder doc): httplib's unbounded request-line read before login (E10) and SO_REUSEADDR port co-binding on Windows — keep the panel on a trusted/management network.

## Tests (tests/test_http*.cpp or a new tests/test_bounceaes_http_hardening.cpp)
Port the encoder's attack tests to the BounceAES server: smuggled /api/setup inside text/plain, multipart, gzip, HEAD, Range, > 1 MB, chunked, no-length bodies and pipelining → password stays unset, connection closed; Host check (evil.example 403, 127.0.0.1/localhost/[::1] OK); setup race; throttle (with a clock hook); SSE closes after logout and doesn't extend the session; password change revokes; lost-stop race (50 start/stop pairs). Existing BounceAES HTTP/panel tests stay green. Windows-specific tolerance only where a reset can swallow a response (as in the encoder tests).
