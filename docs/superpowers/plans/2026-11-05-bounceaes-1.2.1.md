# BounceAES Master 1.2.1 — plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Two follow-ups announced with 1.2.0: a source removed from a playing mix fades out instead of stepping, and rerouting one channel pair of a multichannel Windows card no longer restarts the card's other pairs.

**Architecture:** (1) The mixer keeps a removed member as "leaving" and ramps it to 0 over `kMixRampFrames` before dropping it. (2) The decision how a device's request changes the running bridge streams becomes a pure, host-tested core function; the bridge applies "update feeds" to a running `RenderStream` through an RT-safe feed table and restarts the device stream only when its `max_delay` (and with it the pacer's read position) changes.

**Spec:** `docs/superpowers/specs/2026-11-03-bounceaes-mixing-design.md` (1.2) plus the 1.2.0 release notes (rulings R13, R14).

### Task 2: Bridge — reroute a channel pair without restarting the card

**Files:** create `core/include/bam/render_layout.hpp`, `core/src/render_layout.cpp`, `tests/test_render_layout.cpp`; modify `bridge/bridge_main.cpp`, `bridge/wasapi_stream.hpp`, `bridge/wasapi_stream.cpp`.

- [ ] **Step 1 (RED):** a pure function, host-tested:
  ```cpp
  struct RenderFeed { int channel_pair; ShmSource kind; int pair; uint32_t delay; };
  struct DeviceLayout { std::string endpoint; uint32_t max_delay; std::vector<RenderFeed> feeds; };  // feeds sorted by channel_pair
  enum class DeviceAction { Keep, UpdateFeeds, Restart, Start, Stop };
  // groups request dests (win-out ids + kind/pair/delay/channel_pair) by endpoint
  std::vector<DeviceLayout> device_layouts(const std::vector<BridgeDestReq>& dests);
  // what to do with a running device given its previous and new layout
  DeviceAction plan_device(const DeviceLayout* previous, const DeviceLayout* next);
  ```
  Rules: no previous → Start; no next → Stop; equal feeds → Keep; same `max_delay`, different feeds (pair added/removed/rerouted) → UpdateFeeds; different `max_delay` → Restart. Tests for each rule, plus grouping (pairs of one endpoint together, `#N` parsed via `parse_dest`, sorted by channel_pair, max_delay = max feed delay).
- [ ] **Step 2:** `RenderStream`: add `void update_feeds(std::vector<RenderFeed> feeds)` callable from the bridge thread while the render thread runs. RT-safe hand-over: a fixed-size feed table (at most `kDeviceCount` pairs) double-buffered with an atomic index/sequence, or `std::atomic<std::shared_ptr<const …>>` only if it is lock-free on MSVC and MinGW — prefer the fixed double buffer. The render thread picks the new table at the start of a pass; channels of pairs that disappear play silence from that pass on (no reopen). Per-dest slot state reporting follows the new pairs.
- [ ] **Step 3:** `bridge_main.cpp`: one slot per endpoint (key `"dst|" + endpoint`), store its `DeviceLayout`; each request: compute layouts, call `plan_device` per endpoint and apply (Keep / `update_feeds` / restart: reset then create / create / erase). Unrelated devices untouched.
- [ ] **Step 4:** host tests for the pure function; `cmake --build build-win -j8` and `build-win32` without warnings (the bridge cannot run here; review by reading); commit `bridge: reroute a channel pair without restarting the card`.
